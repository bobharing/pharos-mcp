# Phase 2: Bun Migration

## Objective

Convert the project from Node.js + npm + tsc to run natively on Bun. After this phase, the server runs directly from TypeScript source with `bun run src/index.ts` — no compilation step needed for development.

## Prerequisites

- Phase 1 complete (duplicate runs fixed)
- Bun installed on the system (`bun --version` should work)

## Files to Modify/Create/Delete

| Action | File |
|--------|------|
| Modify | `package.json` |
| Modify | `tsconfig.json` |
| Modify | `src/index.ts` |
| Modify | All `src/**/*.ts` files (import extensions) |
| Delete | `package-lock.json` |
| Create | `bun.lock` (auto-generated by `bun install`) |

## Implementation

### Step 1: Update `package.json`

```jsonc
{
  "name": "pharos-mcp",
  "version": "1.5.0",
  "description": "MCP server for web performance auditing using Lighthouse",
  "main": "src/index.ts",
  "bin": {
    "pharos-mcp": "src/index.ts"
  },
  "type": "module",
  "scripts": {
    "start": "bun run src/index.ts",
    "dev": "bun run --watch src/index.ts",
    "test": "bun test",
    "test:coverage": "bun test --coverage",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "build": "bun build src/index.ts --outdir dist --target node",
    "smoke:profile": "bun run scripts/smoke-profile.ts"
  },
  "engines": {
    "bun": ">=1.1.0"
  },
  // ... rest unchanged
}
```

Key changes:
- Remove `"main": "dist/index.js"` → `"main": "src/index.ts"`
- Remove scripts: `prepare` (husky), `prepublishOnly`
- Change `start` from `node dist/index.js` to `bun run src/index.ts`
- Change `dev` from `tsx src/index.ts` to `bun run --watch src/index.ts`
- Change `test` from `vitest` to `bun test`
- Change `build` to `bun build` (optional, for publishing only)
- Remove `engines.node`, add `engines.bun`

### Step 2: Update `tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "outDir": "./dist",
    "rootDir": "./src",
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "declaration": true,
    "esModuleInterop": true,
    "allowSyntheticDefaultImports": true,
    "resolveJsonModule": true,
    "allowImportingTsExtensions": true,
    "noEmit": true,
    "types": ["bun-types"]
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "coverage", "**/*.test.ts", "**/*.spec.ts"]
}
```

Key changes:
- `"module": "ESNext"` (was `"Node16"`)
- `"moduleResolution": "bundler"` (was `"Node16"`)
- `"allowImportingTsExtensions": true` (was `false`)
- `"noEmit": true` (tsconfig is for type-checking only now)
- `"types": ["bun-types"]` (was `["node"]`)

### Step 3: Convert all imports from `.js` to `.ts` extensions

Every import in `src/` that ends with `.js` must be changed to `.ts`:

```typescript
// Before
import { runLighthouseAudit } from "./lighthouse-core.js";

// After
import { runLighthouseAudit } from "./lighthouse-core.ts";
```

Apply to ALL files in `src/` including `src/tools/`.

### Step 4: Replace `__dirname` pattern in `src/index.ts`

```typescript
// Before
import { readFileSync } from "fs";
import { join, dirname } from "path";
import { fileURLToPath } from "url";

const __dirname = dirname(fileURLToPath(import.meta.url));
const packageJson = JSON.parse(readFileSync(join(__dirname, "..", "package.json"), "utf-8"));

// After
const packageJson = await Bun.file(import.meta.dir + "/../package.json").json();
```

### Step 5: Update shebang in `src/index.ts`

```typescript
// Before
#!/usr/bin/env node

// After
#!/usr/bin/env bun
```

### Step 6: Remove Node-only dev dependencies

Remove from `devDependencies`:
- `tsx` (Bun runs TS natively)
- `vitest`, `@vitest/coverage-v8`, `@vitest/ui` (replaced by `bun:test`)

Add to `devDependencies`:
- `@types/bun` (for Bun type definitions)

### Step 7: Delete `package-lock.json` and install with Bun

```bash
rm package-lock.json
bun install
```

This generates `bun.lock`.

### Step 8: Update `.gitignore`

Add `bun.lock` if you want it tracked (recommended), or ensure it's not ignored. Remove references to `package-lock.json` if present.

## Acceptance Criteria

- [ ] `bun run src/index.ts` starts the MCP server without errors
- [ ] `bun test` discovers and runs test files (tests may need migration — see Phase 6)
- [ ] No `*.js` import extensions remain in `src/`
- [ ] `tsc --noEmit` passes (type-checking only)
- [ ] `package-lock.json` is deleted
- [ ] `bun.lock` exists

## Notes

- The `lighthouse` package is large and Node-native. It should work under Bun but needs end-to-end smoke testing (run `bun run scripts/smoke-profile.ts --url https://example.com`).
- If Lighthouse has issues under Bun, the fallback is to keep `lighthouse` running via its own Node subprocess — but try direct execution first.
- ESLint and Prettier remain unchanged (they work fine under Bun).
